The one insight that mattered

Turning on xunit parallelism alone barely moved the needle (24.5s → 22s), because container & fixture startup was a ~20s floor that every run paid up front. The big lever was starting the three Testcontainers concurrently with Task.WhenAll. Parallelism then compresses the test-execution slice on top of the lower floor.

The three changes that did the work

Focused before/after snippets from TestFixture.cs, TestBase.cs and the new assembly-fixture file.

1 · biggest wall-clock win

Start the 3 containers concurrently

PeakLims/tests/PeakLims.IntegrationTests/TestFixture.cs — sequential await … StartAsync() → two Task.WhenAll waves.

2 · enables parallelism

Assembly fixture, not collection fixture

One shared container set across parallel classes. An ICollectionFixture would spin up N sets; the global [Collection] serialized every class.

3 · parallel safety

Scoped mocks + real AsyncLocal HttpContext

Singleton mocks shared mutable state across concurrent tests. Scoped mocks give each TestingServiceScope its own; the real IHttpContextAccessor isolates the current user per async flow.

3 latent bugs parallelism exposed

All three were order-dependent tests that never validated their own inserted rows — they silently counted other tests' rows accumulating in the shared DefaultTestingOrganizationId. Serial execution hid them.

org-scoped filter

AccessionContact

Fake inserted a child with no org-defining parent, so the org-scoped query filter excluded it. Fix: attach contacts to an accession in the org.

org-scoped filter

Sample

Same shape: samples are filtered by the owning patient's org. Fix: attach samples to a Patient before insert.

cross-test blast radius

AccessionAttachment

List projection pre-signs an S3 URL for every in-scope attachment and threw ValidationException: S3 bucket not set on another test's bucketless row. Fix: run in a dedicated PeakOrganization.

xunit versions & updates

The package naming and the version numbers are genuinely confusing, so here is the whole picture plus how to bump.

The package split

xunit v2 · 2.9.3 is the classic package — kept for the Unit & Functional projects.

xunit.v3 is the rewrite: self-contained exe (MTP), ValueTask lifetimes, [assembly: AssemblyFixture], typeof-based attributes. Only IntegrationTests uses it.

"v4 preview" is a misnomer

The framework generation is xunit v3. 4.0.0-pre is just the 4th major of the xunit.v3 package — still prerelease. A stable 3.2.2 line already exists.

Reusable recipe: assembly-fixture parallelism

any repo

A repo-agnostic checklist to give any xunit v3 integration suite one shared set of expensive resources (containers, DB) while classes run in parallel. This is the pattern behind [assembly: AssemblyFixture(typeof(TestFixture))].

1Register the fixture at the assembly level, in its own file

[assembly: …] attributes cannot live inside a file-scoped namespace X; block — use a dedicated file (e.g. AssemblyFixtureRegistration.cs).

using Xunit;
[assembly: AssemblyFixture(typeof(TestFixture))]

Created once before any test, disposed after all tests — one instance shared across every class. That is what lets classes share containers.

2Remove ICollectionFixture and any global [Collection]

These are what a typical v2 shared-context suite uses — and exactly what serializes everything.

  • ICollectionFixture<T> + [CollectionDefinition] scope the fixture to a collection.
  • A global [Collection(...)] on your base class puts every test in one collection → serial.
  • Delete both. With no collection attribute, each class is its own collection and classes parallelize.
3Make the fixture parallel-safe — mandatory, not optional
"there is no change in parallelization when using an assembly fixture … fixtures used as assembly fixtures may be used from multiple tests simultaneously, and must be designed for with this parallelism requirement in mind." — xunit docs
  • Register per-test mutable services as scoped, not singleton (permissions, jobs, current user).
  • Prefer real AsyncLocal-backed services (e.g. IHttpContextAccessor) over singleton mocks — AsyncLocal isolates per async flow.
  • Any shared mutable field on the fixture must be thread-safe.
  • One-time global config (AutoFaker/Bogus) goes in the fixture's InitializeAsync, not a per-test constructor.
4Access the fixture — either style works
  • Constructor injection: public MyTests(TestFixture fixture) — xunit passes the single instance.
  • Static handoff: expose a static accessor (this repo uses static IServiceScopeFactory BaseScopeFactory via TestingServiceScope). Handy when a helper needs it without threading it through every constructor.
5Migrate the fixture to the v3 API
  • IAsyncLifetime.InitializeAsync / DisposeAsync return ValueTask (not Task); IAsyncLifetime now implies IAsyncDisposable.
  • Assembly attributes take typeof(T), not a string.
6Start expensive resources concurrently — the real perf win
await Task.WhenAll(db.StartAsync(), mq.StartAsync(), storage.StartAsync());
await Task.WhenAll(Migrate(db.ConnectionString), SeedStorage(storage)); // each needs a running container
7Project + runner setup
  • .csproj: xunit → xunit.v3; add <OutputType>Exe</OutputType>; copy xunit.runner.json to output.
  • xunit.runner.json: parallelizeTestCollections: true; tune maxParallelThreads ("1x" = one per core; past ~cores shows diminishing returns when one shared DB is the contention point); parallelAlgorithm: conservative.
  • Run the built exe/dll directly: dotnet path/to/Tests.dll [-parallel none|collections -maxThreads N]. dotnet test may fail if the SDK dropped VSTest for MTP.
8Expect to fix latent order-dependent tests

Serial execution hides tests that never validate their own inserted data — they silently count rows other tests leave in a shared scope. Make each test self-sufficient (own parent/org, or a dedicated tenant). Parallelism will surface these; treat it as part of the migration, not a surprise.
